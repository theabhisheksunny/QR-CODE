# Deep cleanup of Universal QR LAN sharing app: dead code, stale ports, PostgreSQL removal

This review covers the four cleanup commits (`ce002a3`, `32b62cf`, `57bc68e`, `333e16e`) layered on base `f43e96a`. The work strips the repository of agent-generated artifacts, dead Java symbols left over from the pre-LAN architecture, an obsolete PostgreSQL/Flyway dependency surface, and a pervasive stale port (8080 vs. the current 8787). It also repairs the e2e suite, which was coupled to a now-deleted `services-status.json` handoff file, and adds a `CONTRIBUTING.md`. The net change is +1525/−3383 across 73 files, overwhelmingly deletion. All verification was re-run independently against the merged tree, not taken on faith from the fixer's recorded findings.

Watch for: nothing blocking. The one residual `8080` string lives in `CONTRIBUTING.md` as deliberate "the port is NOT 8080" documentation (confirmed). `e2e/package-lock.json` stays tracked despite a new ignore rule, which is an intentional minimal-change decision (confirmed).

**Verdict**: APPROVED

## High-level view

The deletions are the bulk of the change and the lowest-risk part: agent scratch files under `.agents/tasks/` (only the planning `.md`/`.json` and `features/*.json` survive), the generated frontend bundle under `backend/.../static/`, the Flyway migration SQL and its parent `db/` tree, and three report files (`FINAL-REPORT.md`, `e2e/TEST-SUMMARY.md`, `test-report.html`). None of these are referenced by build or runtime, and the backend still compiles and tests green after removal.

The Java dead-code removal is surgical and symbol-scoped. Five members that no live code path reaches — `AppProperties.baseUrl`, `TokenUtil.hashToken`, the no-arg `NetworkService.getShareBaseUrl()`, `FileShareService.getFileByToken`, and `FileMetadataResponse.qrCode` — are gone, along with their now-orphaned imports, YAML keys, and test methods. The surviving `getShareBaseUrl(int port)` overload and the three legitimately-used `qrCode` references in other DTOs were correctly left alone.

The port and config correction is the widest-reaching behavioral fix. The repo had drifted between the old 8080 and the current 8787 across the Dockerfile, nginx proxy, docker-compose, README, and multiple e2e specs. These are now consistent on 8787, and the storage path env vars (`FILE_STORAGE_PATH`, `METADATA_STORAGE_PATH`) are threaded through the Dockerfile and compose file instead of a hardcoded `/data/temp-files`.

The database teardown removes PostgreSQL as a surface entirely: the compose `postgres` service and volume, the `DATABASE_*` env vars in `.env.example` and compose, and the Flyway DDL. This finishes removing vestigial infra; the running filesystem-metadata design was already in place on the base branch.

The e2e repair is the most behaviorally interesting piece. The specs previously read a `services-status.json` file that an agent step wrote at runtime; with that file deleted, the specs now derive URLs from `process.env` with sane localhost defaults. The `03-file-upload` spec also had a wrong assertion that expected the share URL to be the API download endpoint — it now correctly asserts the SPA `/share/<token>` route and downloads through the API URL separately.

### Symbol-scoped Java dead-code removal

The five removed members were each verified absent from `backend/src/main/java` by repo-wide search, and the removal correctly stopped at the dead symbols rather than the files that contain them. `AppProperties.baseUrl` is gone but `serverPort` stays, because `FileShareService.buildShareUrl` still calls `appProperties.getServerPort()`. `NetworkService` lost both the no-arg `getShareBaseUrl()` and the `@Value("${server.port}")` field that only fed it, while the parameterized `getShareBaseUrl(int port)` — the one the controller actually uses — is untouched. The `qrCode` removal targeted only `FileMetadataResponse`; the identically-named fields in `QrValueResponse`, `FileUploadResponse`, and `QrCodeService` are live and were left in place.

Orphaned imports were cleaned alongside the symbols: `MessageDigest`/`NoSuchAlgorithmException` in `TokenUtil`, the Spring `Value` import in `NetworkService`, and `FileExpiredException` in the test that lost its only user. The matching test methods (`testHashToken*`, `testGetFileByToken_expired`) were removed, leaving `TokenUtilTest` with exactly its three `generateToken` cases. This is why the suite still reports a clean 27 tests rather than silently dropping coverage of surviving behavior.

### Port and storage-path consistency on 8787

The Dockerfile now builds and runs on `eclipse-temurin-21`/`eclipse-temurin:21-jre`, exposes 8787, creates `/app/storage/files` and `/app/storage/metadata`, and sets `FILE_STORAGE_PATH`/`METADATA_STORAGE_PATH` as env before the entrypoint. The nginx `/api` block proxies to `backend:8787`, and docker-compose publishes `8787:8787` with the same storage env and an `app_storage` named volume. The README no longer contains any `8080` occurrence. The only remaining `8080` string in the repo is in `CONTRIBUTING.md`, where it is a deliberate statement that the port is not 8080 — a documentation guardrail, not a stale reference.

### PostgreSQL surface fully removed

```
base branch:  app → (filesystem metadata)  +  leftover postgres service/volume/env/DDL
after cleanup: app → (filesystem metadata)
```

The compose `postgres` service, `postgres_data` volume, and all `DATABASE_*` environment variables are gone from both `docker-compose.yml` and `.env.example`; the `backend/src/main/resources/db/` tree (holding `V1__create_shared_files.sql`) no longer exists. Flyway was already absent from `pom.xml` on the base branch, so this DDL was unreachable dead infrastructure.

### e2e decoupled from the runtime handoff file

The specs `01`, `02`, `03`, `10`, and `11` previously parsed a `services-status.json` that an orchestration step produced at runtime to publish the frontend/backend URLs. That file is deleted, so every spec now resolves its base URL from `process.env.BASE_URL` (or `API_URL`) with a localhost default. No `services-status` reference remains anywhere under `e2e/**/*.ts`. Where `fs`/`path` were still needed for the `test-results` screenshot directory, those imports were correctly retained.

The `03-file-upload` spec carried a genuine assertion bug, not just a coupling issue: it expected `data.shareUrl` to match `/api/files/share/` and then fetched the download directly from `shareUrl`. But `shareUrl` is the SPA route `http://host:8787/share/<token>`, not the download endpoint. The fix asserts `shareUrl` matches `/\/share\/[A-Za-z0-9_-]+$/` and explicitly `not.toContain('/api/files/share/')`, then extracts the token and downloads via `${API_URL}/api/files/share/${token}`. This makes the test exercise the real two-surface contract (SPA route for humans, API path for bytes) instead of a URL shape that never existed.

Port hardcoding was also removed from the raw-socket paths: `07-security` builds its request port from `parseInt(new URL(API_URL).port) || 8787`, and `demo-live.spec.ts`/`live-demo.ts` parse `API_URL` for hostname/port rather than literal `localhost:8080`, with the hardcoded Windows storage path in `live-demo.ts` replaced by `./backend/storage/`.

### Tooling config added to make lint and typecheck runnable

Two tooling gaps surfaced during verification and were fixed with user approval: `frontend/.eslintrc.cjs` was added (ESLint 8 legacy config for the existing `@typescript-eslint` + react-hooks + react-refresh devDeps) so `npm run lint` resolves a config, and `e2e/package.json` pinned `typescript ^5.4.5` so `npx tsc` uses the repo-intended 5.x rather than an environment-global TS 7. These are build-enablement changes bundled into the cleanup rather than cleanup proper; both commands now exit 0.

Backend: `mvn test` → `Tests run: 27, Failures: 0, Errors: 0, Skipped: 0`, `BUILD SUCCESS`. Frontend: `npm run build` exits 0 (tsc + vite), `npm run lint` exits 0 at `--max-warnings 0`. These were executed in this review, not read from the fixer's `findings` fields, which independently corroborate the same results.

Not re-run here: the Playwright e2e suite itself (requires both services live on the LAN). The spec-level changes were verified by reading the specs and by the fixer's recorded `npx tsc --noEmit` pass; actual end-to-end execution against running services was not performed in this pass.
